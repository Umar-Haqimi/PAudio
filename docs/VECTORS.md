# PAudio — golden test vectors

Source of truth for how the nine golden vector sets (SPEC §7.1) are produced, where they live and how tightly they must match.
Written in M0 (2026-11-20). Sets 1–4 and 6 are built in **M2**, 5/7/8 in **M3**, 9 in **M4**.

## Principles
1. **Independent oracles.** Every JSON file is generated by Python in `tools/golden/` that is written from the *specification and the upstream sources*, never by porting the Kotlin. Kotlin tests only read the JSON.
2. **Committed outputs.** The generated JSON is committed (CI has no Python requirement). Regenerate only deliberately; bump `algoVersion` (SPEC §5.6) if a set changes meaning.
3. **Determinism.** No unseeded randomness (`numpy.random.default_rng(<seed>)`), no wall-clock, no platform-dependent formatting. Floats are written with `repr()` (shortest round-trip), no NaN/Inf (use `null`).
4. **Self-describing files.** Top-level object: `{"set": "<name>", "formatVersion": 1, "generator": "tools/golden/<script>.py", "python": "...", "numpy": "...", "scipy": "...", "tolerance": {...}, "cases": [ ... ]}`.
5. **Tolerances are asserted in Kotlin from the file's `tolerance` block** (not hard-coded twice).

## Environment (Arch Linux, from SPEC §7.1)
```bash
python -m venv .venv && . .venv/bin/activate && pip install numpy scipy
python tools/golden/gen_all.py --out core                 # writes core/*/src/test/resources/golden/*.json
python tools/golden/gen_all.py --out core --check         # (to be implemented in M2) regenerate to a temp dir and diff against the committed files within tolerance
```
`gen_all.py` calls one module per set (`gen_rbj.py`, `gen_kweight.py`, `gen_pchip.py`, `gen_loudness.py`, `gen_measurement.py`, `gen_dpmap.py`, `gen_stimulus.py`, `gen_hw.py`, `gen_pref.py`) and accepts `--only <set>` for a single file. Python ≥ 3.11, numpy ≥ 2, scipy ≥ 1.13 (the M0 research machine had numpy 2.5.3 / scipy 1.18.1). Dev-only; nothing in `tools/golden/` is shipped.

### Set 1 — RBJ magnitudes
- Filters (SPEC §2.1.3): low-shelf `fc=105 Hz, Q=0.707`; peaking `fc=3000 Hz, Q=0.8`; high-shelf `fc=8000 Hz, Q=0.707`; fs = 48000 Hz; RBJ Audio-EQ-Cookbook coefficients (https://www.w3.org/TR/audio-eq-cookbook/) with `A = 10^(dBgain/40)`, shelf slope via `Q` (use the Q-form: `alpha = sin(w0)/(2Q)`, shelf terms `2·sqrt(A)·alpha`).
- Gains: −12, −9, −6, −3, 0, +3, +6, +9, +12 dB (9 values) × 3 filter types.
- Frequency grid: 1/24-octave from 20 Hz to 20 kHz inclusive: `f_i = 20 · 2^(i/24)` for `i = 0…240` clipped to ≤ 20000 (grid used everywhere; `GRID_F`).
- Case record: `{"type": "lowshelf|peaking|highshelf", "gainDb": g, "magDb": [..len(GRID_F)..]}`; file also stores `"gridHz"` once.

### Set 2 — K-weighting
- BS.1770 Annex 1 coefficients at 48 kHz (verify against the ITU-R BS.1770-5 text before freezing): pre-filter `b = [1.53512485958697, −2.69169618940638, 1.19839281085285]`, `a = [1, −1.69065929318241, 0.73248077421585]`; RLB high-pass `b = [1, −2, 1]`, `a = [1, −1.99004745483398, 0.99007225036621]`. Cascade magnitude in dB (no −0.691 dB offset in the magnitude; record that the loudness constant is not applied).
- Frequencies: exact 1/3-octave centres `1000·10^(n/10)`, `n = −17…+13` (31 centres ≈ 20 Hz…20 kHz) — the JSON stores both the exact centres and nominal labels. Case: `{"fcHz": .., "kDb": ..}`.

### Set 3 — PCHIP
- Knots: the nine test frequencies `F = {1000, 2000, 3000, 4000, 6000, 8000, 10000, 12500, 14000}`; x = `log2(f)`.
- Ten threshold (gain) sets in dB (seeded for the random ones; include: all-zero, monotone rising, monotone falling, single peak, single notch at 4 kHz, plateau (repeated values → PCHIP flat segments), alternating ±, steep step at 8 kHz, ramp with a censored-style clamp, random seed 1). Evaluate at the 1/24-octave grid points inside [1000, 14000] **and** at all nine knots (must reproduce knot values exactly, ≤ 1e-9).
- Do **not** test extrapolation here (outside 1–14 kHz the hold/fade rules of SPEC §2.1.3 apply and are covered by set 5).

### Set 4 — Loudness predictor
`ΔL(G) = 10·log10( Σ_b P_b·|K(f_b)|²·10^(Ḡ_b/10) / Σ_b P_b·|K(f_b)|² )` over the 1/3-octave bands of set 2 (SPEC §2.1.5).
- Cases: (a) flat G = 0 → ΔL = 0; (b) broadband +6 dB → +6.00; (c) each axis alone (bass shelf, presence peak, treble shelf of SPEC §2.1.3) at ±6 dB with **pink** weighting (`P_b` equal per 1/3-octave); (d) the same with a synthetic non-flat LTAS (seeded); (e) **M4 re-run**: each clip's LTAS JSON from `tools/assets/ltas.py` (Discipline / Echoplex / 34 Ghosts IV, see `DECISIONS.md` §12).
- `Ḡ_b` = mean of G (dB) over the grid points inside band b, power-averaged across the two ears (`10·log10(mean(10^(G_ear/10)))`); both ears identical in axis cases, different in at least one asymmetric case. Define band edges at `fc·2^(±1/6)`.

### Set 5 — Measurement model (SPEC §2.1.3)
Twelve threshold sets (per ear, 9 frequencies, dBFS; `L_ref` given): **normal**, **sloping HF loss**, **notch at 4 kHz**, **asymmetric (L worse by ≥15 dB over ≥2 adjacent bins)**, **asymmetric below the 15 dB rule (negative control)**, **censored points at 12.5/14 kHz**, **all censored HF**, **flat loss**, **very good hearing (HL_est below −10 dB, display clamp)**, **unreliable catch-trial case (reliability flag only)**, **one ear with a censored 1–2 kHz anchor**, **both ears identical**.
Per case expected: `N(f,ear)`, `A`, `HL_est(f,ear)`, `PTA3(ear)`, WHO grade of better ear PTA3 (string), `EHF(ear)`, asymmetry flag, `g_h` on the 1/24-octave grid (half-gain `s ∈ {0.5, 1.0}`, caps −6/+12, PCHIP in log2 f, sub-1 kHz `w(f)` ramp to 250 Hz, 14–16 kHz hold, 16–20 kHz fade), the preference-axis settings `(gB,gP,gT)`, final `G = clamp(g_h + g_p, −12, +15)`, preamp `P = −max(0, max G) − 0.5` floored at −15. `R_df` values are the spec table (verified against USAARL Table 11-1 in `DECISIONS.md` §15).

### Set 6 — DP band mapping (**normative oracle: DECISIONS.md §1**)
Inputs per case: `fs ∈ {44100, 48000}`, `frameMs = 16.0`, curve name, per-ear `G(f)` on the 1/24-octave grid (the 12 curves of set 5 for both ears plus the extremes: max bass +12, max presence +6, max treble +8 shelf curves).
Expected outputs: `blockSize` (1024), `stops` (int list), `cutoffsHz` (double list, last = fs/2), `bandGainsDb[ear]` (float list), `reconDb[ear]` on `gridHz ∩ [50, 16000]`, `reconRmsDb[ear]` (RMS of `recon − G`).
**Acceptance (SPEC §2.1.4): `reconRmsDb ≤ 0.5` for every case**; M0 simulations gave ≤ 0.12 dB (87 bands, N = 1024). Oracle reference implementation (verified runnable; reproduced here so the M2 engineer does not re-derive it):

```python
import numpy as np

def dp_block_size(fs: int, frame_ms: float) -> int:            # EffectDynamicsProcessing.cpp:234-245 + DPFrequency.cpp:137-150
    d = int(np.float32(frame_ms) * np.float32(fs) / np.float32(1000.0))
    n = 8 if d < 8 else (d if (d & (d - 1)) == 0 else 1 << d.bit_length())
    return int(min(max(n, 8), 16384))

def band_stops(n: int, target: int = 128) -> list[int]:        # strictly increasing integer bin indices, ends at n/2
    return [0] + sorted({int(round(x)) for x in np.geomspace(1, n // 2, target)})

def band_cutoffs(stops, fs, n): return [s * fs / n for s in stops]          # last == fs/2

def band_gains_db(stops, fs, n, g_of_f):                         # dB-mean of G at the bin centres of each band
    out, start = [], 0
    for s in stops:
        k = np.arange(start, s + 1)
        out.append(float(np.mean(g_of_f(np.maximum(k * fs / n, 20.0)))))
        start = s + 1
    return out

def native_bin_gains(cut_hz, gain_db, n, fs):                    # replica of DPFrequency::updateParameters (PreEQ, inputGain 0 dB, bands enabled)
    vec = np.ones(n // 2 + 1); bin_next = 0
    for fc, g in zip(cut_hz, gain_db):
        start, stop = bin_next, int(0.5 + fc * n / fs); bin_next = stop + 1
        for k in range(start, min(stop, n // 2) + 1):
            vec[k] = 10 ** (g / 20)
    return vec

def reconstruct_db(vec, n, fs, f_hz):                            # NORMATIVE: linear-in-dB interpolation between bin centres
    return np.interp(f_hz, np.arange(n // 2 + 1) * fs / n, 20 * np.log10(vec))
```
The generator must additionally run a **self-check** (not exported): a bit-exact overlap-add simulation (sqrt-Hann symmetric window of length N, hop N/2, rFFT × `vec` → iFFT, same window, steady-state sine projection at ≥ 24 test frequencies) and assert `|simulated − reconstruct_db| ≤ 0.35 dB` max and ≤ 0.1 dB RMS. (M0 measured 0.05 dB max / ≤ 0.10 dB RMS on smooth curves; `simulate_db` is in the scratch file `sim/oracle_dp_snippet.py`.) If the self-check ever fails the generator aborts — it means the DP model in DECISIONS.md §1 is wrong, not the Kotlin.
Also include negative controls (expected in the JSON as `"specLayout40"` with its worse `reconRmsDb`) for the spec's 40-band `c_k` layout so a reader can see why it was rejected; Kotlin does **not** assert ≤ 0.5 on those.

### Set 7 — Stimulus synthesis (SPEC §2.1.2, §2.2 #4, §4)
Parameters per case: `fs ∈ {48000, 44100}`; tone `{1 kHz pure, 8 kHz warble, 14 kHz warble}`; level −40 dBFS (peak amplitude `A = 10^(−40/20)`); ear `{L, R}`; pulse = 225 ms including **25 ms raised-cosine on/off ramps** `r(t) = 0.5·(1 − cos(π·t/25 ms))` (and mirrored at the end); warble = ±5 % sinusoidal FM at 8 Hz: `f_inst(n) = f·(1 + 0.05·sin(2π·8·n/fs))`, phase accumulated as `φ[n] = φ[n−1] + 2π·f_inst(n)/fs` starting at `φ[−1] = 0`; pure tones `φ[n] = 2π·f·n/fs`; sample `x[n] = A·r[n]·sin(φ[n])`. The opposite channel is exactly `0.0`. (Proposal to freeze in M3; the M3 engineer may refine details but must update this paragraph and the generator in the same commit.)
Expected: first 2048 samples (float, both channels), `peak`, `rms`, steady-state peak (±0.05 dB of target), spectral energy inside ±12 % of `f` vs outside in dB (Hann-windowed FFT of the full pulse; gate ≤ −50 dB relative, SPEC §7.2), ramp endpoint values.
Samples tolerance 1e-6; stats 0.01 dB.

### Set 8 — Hughson-Westlake scripted sequences
Eight scripts with exact expected level sequences and thresholds. Rules (SPEC §4 "Quick detail", normative): start level `L_exp + 20` (or other ear + 15), clamp ≤ `L_max`; not heard → +10 until heard (or censor at `L_max`); then heard → −10, not heard → +5; threshold = lowest level with ≥2 "heard" in ≤3 ascending presentations at that level; max 15 trials per point; fallback = mean of last 4 reversal levels flagged low-confidence.
File format per case: `{"name", "Lexp", "Lmax", "startOverride": null, "responses": "YNY…", "levels": [..per presentation..], "reversals": [..], "thresholdDb": x|null, "censored": bool, "lowConfidence": bool, "trials": n}`.

### Set 9 — Preference bisection
Scripted choice sequences (SPEC §4 flow 5): rounds interleave axes B, P, T, B, P, T, B, P, T; per axis centre `c = 0`; each round compares `c − s` vs `c + s` (A/B side randomisation is irrelevant to the result: record the picked **value**, not the side); picking sets `c` to the picked value and halves `s`; "Can't tell" ends that axis. Initial steps/clamps: bass `s₀ = 6`, `c ∈ [−6, +12]`; presence `s₀ = 4`, `c ∈ [−6, +6]`; treble `s₀ = 5`, `c ∈ [−8, +8]`. Cases: always-low, always-high, alternating, can't-tell at round 2 for one axis, can't-tell immediately for all axes, clamp hit on bass upper bound, mixed. Expected: per-round `(axis, a, b, picked)` and final `(gB, gP, gT)` (exact). Hand-derived; document each in this file when M4 is done.

## Policy for changing vectors
Changing a generator or a tolerance requires: (1) updating this file, (2) regenerating the JSON, (3) a commit message that states why, (4) bumping `algoVersion` if the *meaning* of a computed quantity changed.
